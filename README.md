## 首尔机房是真落在韩国吗

判断一台“韩国 VPS”真假，看三样东西：上游 AS 号、IP 归属、以及 geo 库把它判成哪国。Evoxt 首尔的主出口是 KT（AS4766），韩国最大的固网运营商之一，机房另外接入 KINX（韩国互联网交换中心）。IP 是单 ISP 的 KT 原生段，geo 检测基本都读成韩国。

这件事的实际影响在于绕路。市面上一些标着“韩国”的机器，流量实际从东京或大阪出海，再打回韩国，首尔到东京单程就要 30 到 40 ms，来回一趟白送六七十毫秒，geo 还可能判成日本，解锁全废。真机房的价值就是把这段路砍掉。第三方测评（gwvpsceping）测过 Evoxt 首尔节点，机房内部延迟约 1 ms，主频实测落在 4192 MHz 附近，NVMe 顺序读写 I/O 大约 1672 MB/s。

官方标称单核 Turbo 最高 6.0 GHz，实测 4.2 GHz 更接近真实负载下的表现，这两个数字不冲突，前者是睿频上限。即便按 4.2 GHz 算，跑单线程敏感的活（TLS 握手、游戏服主线程、抓取脚本）也比常见 2.4 GHz 的云主机痛快。

这是选韩国机器最容易踩空的地方，也是各家测评写得最少的部分：

| 运营商 | 回程路径 | 延迟 | 实际表现 |
| --- | --- | --- | --- |
| 电信 | KT → AS163（电信骨干）直连 | 约 40–50 ms | 高峰期有丢包 |
| 联通 | KT → AS4837（联通 169）直连 | 约 45–50 ms | 直连，晚高峰基本稳定 |
| 移动 | KT → CMI → 东京 CMI → 国内 | 略高于前两者 | 绕日本，但抖动小 |

三网都是普通直连，没有走 CN2 GIA、9929 这类优化专线，别指望它有 premium 线路的晚高峰表现。联通和移动用起来比较舒服，移动虽然绕东京，路由稳定，掉速不明显。

电信用户要留意高峰丢包这一条。同一家服务商在优化线路上给了香港（CMI）和马来西亚（CN2 + 9929）两个节点，韩国这台不是。如果你的主力是电信宽带，先拿测试 IP 在晚八点到十一点跑一轮 ping 和丢包统计，再决定买不买；懒得测就直接考虑它的优化线路节点。
